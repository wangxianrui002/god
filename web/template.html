01

题目与做法

只有一句话的题目，怎么把它变成一份可复现的实验

教材第 50 页第 7 章「综合练习」全文只有一句：「应用上述算法思想对股票、房价 （新房、二手房）进行预测，或者根据一些个人信息对要购买的物品进行推荐。」 没给数据、没指定算法、没给评分标准。所以选题、取数、建模、交付全部自定。

本项目选北京二手房，做了两版并存的流水线。用 1x 编号就是为了让两版并存但不混淆： 第一版的产出物一个都没动，「换数据」和「换模型」各值多少才算得出来。

第一版 · 01~06

链家北京二手房成交记录，第三方公开采集。 原始 — 条、跨 —– — 年。

只取 — 年单一年份 —— 全量跨 —– — 年，单价年度中位数从 — 涨到 — 元/㎡， 跨 — 倍； 混在一起建模学到的大半是「这套房是哪年卖的」而不是「这套房值多少」。 单一年份因此不需要把「成交年月」放进特征。

清洗后 — 行 × 17 列 （11 数值 + 5 类别）。

第二版 · 10~15

Kaggle 北京二手房挂牌数据，字段更全。 清洗后 — 行 （— ÷ — ≈ 1.7 倍）。

多出朝向 / 板块 / 环线 / 带看量等字段， 并且有了小区标识（— 个小区） —— 这一列让第一版承认过却修不了的「交叉验证乐观偏差」第一次可以被量化。

⚠️ 第二版是挂牌价（卖方要价），第一版是成交价， 绝对价格不可比，但 R² 这类相对指标可比 —— 跨版本对比一律用 R²。

为什么目标是「单价」而不是「总价」？因为面积在定义上就被除掉了 —— 实测全市 corr(面积, 单价) = —， 而 corr(面积, 总价) = —。 这就是「预测单价」这个目标选择的全部代价：面积这个最直观的变量几乎不再提供信息。

代价换来的是另一件事：单价六成以上的波动由「在哪个区」决定（区县 η² = —），价格跨度的来源变得可解释。

02

防数据泄露：三道关，关关都不能省

本项目最要紧的正确性问题 —— 加错一列，R² 能凭空高 —

建模前必须过 guard_no_leakage()。它用三道关，每一关抓的是不同种类的泄露：

  1. 列名黑名单（LEAK_NAME_PATTERN）：匹配 价格|总价|单价|首付|万元|_万$|price。
  2. 显式排除列表（DROP_ALWAYS）：totalPrice / communityAverage / 经纬度 / DOM / 各类标识符。
  3. 单特征交叉验证筛查：每个特征单独拿去预测目标，CV R² 超过 — 判为泄露。 这一关不认名字、不认语义，只认实测。

下面这张图是把两个故意留在特征集里的泄露字段送进第三关跑出来的结果。 之所以要真跑一遍而不是「知道它泄露就删掉」，是因为这两列的失败方式完全不同， 而它们的对照正是「为什么不能只看相关系数」的证据。

小区均价 —— 数值判据抓得住，名字拦不住。

列名里没有「价格」二字，黑名单拦不住；相关系数 — 用常见的 0.95 阈值也拦不住。但让它单独预测一次目标，CV R² 就是 —，一测就露馅。 原因是它天然含本行信息 —— 同小区的均价是用包括这一套在内的房源算出来的。

总价_万（第一版）—— 两道数值判据都抓不住，只有语义判断抓得住。

它与目标的相关只有 —、 单特征 R² 只有 —， 两道数值判据都会放它过去。可它是实打实的泄露：

corr(总价_万 × 10000 ÷ 面积, 单价) = —
最大差 — 元/㎡ （这点差就是 CSV 里总价只存到整万元造成的舍入）

换句话说，总价和面积两列一起递进去，等于把目标原样递了进去。 真把它放进特征再跑一遍 Ridge：CV R² 从 — 虚高到 — （—， 见 results/leak_demo.csv）。

为什么数值判据看不见它？因为线性模型自己造不出「比值」这个非线性组合 —— 判据的有效性依赖于测试它用的模型类别。换个能学比值的模型，这一列的 R² 立刻就是 1.0。 所以列名 / 语义那一层不能省，R² 那一层也不能省。

这条也解释了第一版为什么会得出「缺的是数据不是算法」：一个只看单变量解释力的框架， 天然看不见特征之间的组合信息 —— 第四节会看到，这个盲区正是第二版涨分的来源。

第一版：5 个模型，只用教程讲过的算法

自我约束：模型清单不许超出教材范围，看它们能做到什么程度

划分：train_test_split(test_size=0.2, random_state=42) → — 训练 / — 留出； 交叉验证用 KFold(n_splits=5, shuffle=True, random_state=42)。 RMSE 单位均为元/㎡。

5 折交叉验证结果（results/model_scores.csv）

按 5 折 CV R² 降序。蓝色标记 = CV 最高；橙色标记 = 网页实际部署的那个。

冠军 Ridge+Poly2（—） 只比不带多项式的 Ridge 高 —， 而 CV 标准差是 — —— 赢得真实，但赢得很小。

线性回归和 Ridge(alpha=1) 完全同分：11 个数值特征都标准化过、 one-hot 列都是 0/1，本就没什么共线性可罚，正则化在这里没有用武之地。

KNN 比冠军差 —，根因是维度灾难：— 个样本摊在几十维的 0/1 空间里，「邻居」这个概念的区分度就下降了。 把 k 从 1 调到 60 也治不好 —— 它不是参数问题，是特征表示问题。

一个由样本量决定的结论翻转（很值得讲）：同一段代码、同一份数据源， Ridge+Poly2 在 306 行时 CV R² 是 +0.008（多项式彻底失败）， 在 — 行时是 —（5 个模型里排第一）。 多项式把维度撑得很开（现在这份数据的 11 个数值特征经平方和两两乘积是 77 维；当年那 306 行只有 8 个数值特征、展开后 44 维，仍是样本量的 7 倍）， 多出来的维度要靠样本量喂饱。

所以「多项式会不会炸」不是算法的固有属性，而是「模型复杂度 ÷ 样本量」的函数。 这也是本项目为什么要把数据量做到 1 万以上的直接理由。

还有一条容易被当成 bug 的现象：辛普森悖论。 全市合并看 corr(房龄, 单价) = — —— 看起来「房子越老越贵」；可是拆到区县内部就符号混杂 （—，其余为负）； 把每套房的特征与单价都扣掉本区县均值再看，整体只剩 —（见图 fig06）。

真相是老房子集中在核心城区（区内 r 最正的是 —，—）、 新房集中在近郊远郊（最负的是 —，—）。 区县这个「背景变量」同时推着房龄和单价走，合并起来就把区县差异错记成了房龄效应。

第九节可以现场验证：同一个房龄，换一个区县，趋势线的方向会翻过来 —— 图上的实线是该区县自己的趋势，虚线是全市的。

第二版：9 个模型 × 2 套交叉验证

换数据 + 换模型，并且用一把更诚实的尺子重新量一遍

第一版 R² 停在 —，得出的结论是「缺的是数据不是算法」。 这一节把那个结论验证一遍、也修正它。

模型怎么选的：不采用「文献说 X 好就用 X」——那是把别人数据集上的结论硬套过来。 做法是四个 GBDT 全放进去，用自己这份数据实测（选型依据与文献见 MODEL_SELECTION.md）。两组交叉验证并排跑， 超参数在对比阶段一律相同（n_estimators=400, learning_rate=0.06）， 否则「哪个模型好」和「谁调得更狠」会混在一起。

9 个模型 × 2 套 CV（results/model_scores_v2.csv）

按主口径 GroupKFold R² 降序。「乐观落差」= 普通 KFold − GroupKFold， 衡量这套评估被空间自相关高估了多少。

但「谁是第一」要说得很小心：冠军 — （—）领先第三名只有 —， 只有冠军自己的折间标准差 — 的 — —— 正确的说法是「前三个打平」，不是「HistGBR 最好」。 本项目的做法是把「打平」如实写出来，而不是挑一个数最大的当成结论。

⚠️ 堆叠没有赢 —— 这是本项目与文献不一致的地方，如实报告。 文献一致报告堆叠优于任何单一基模型，这份数据上它普通 KFold 第一 （—）、GroupKFold 却掉到第二。

06

反直觉：新字段的一元解释力很低

这张图和模型分数是矛盾的 —— 而矛盾本身就是结论

换数据的动机是「第一版缺朝向 / 楼层 / 小区 / 板块，所以 R² 卡在 0.70」。 换完之后要正面回答一个问题：这些新字段的一元解释力有多大？ 度量用 η²（组间方差 ÷ 总方差），也就是「只看这一个字段，能解释目标多少方差」。

地理维度：看着强，但它不新。

板块（— 个取值）η² = —、环线（— 个取值） — —— 数字很漂亮。

可是第一版的「区县」只有 — 个取值，就有 —； 板块只是把同一件事切得更细，一元解释力只从 — 挪到 —。 地理信息在第一版就已经吃满了。

非地理维度：才是真正新开的信息轴，而它低一个数量级。

朝向 —、装修 —、楼层位置 —（小到可以忽略）—— 三者全部低于 0.05。说「低一个数量级」还是说轻了： 最强的非地理字段 — 对上最强的地理字段 —， 是 — 倍。 作为量级参照：第一版并不算强的「近地铁」，单特征 CV R² 也有 — —— 两者口径不同（η² 是组间方差占比，那是样本外 R²）， 这里只用来比数量级，不做严格比较。

只从这张图看，应该得出「换数据几乎白换」的结论。

可实测模型分数明明涨了 —— 两个数字对不上，而这就是本节的核心结论。 对不上的部分只能来自特征之间的交互：「同一个板块里朝向好的更贵」 「同一个小区里楼层不同价不同」—— 这类信息在任何一个单变量的统计量里都看不见， 它只存在于组合中。

线性模型造不出组合项，树模型按分裂逐层组合，这才把它变成分数。 这正好解释了「换数据」和「换模型」两件事为什么必须一起做： 换了数据但没有能利用交互的模型，这份数据的价值就兑现不了。

但这里有一个第一版没料到的结果：换数据之后连线性模型都涨了 —。原以为「Ridge 造不出交互项、所以吃不下新字段」， 实测它吃得下不少 —— 多出来的解释力来自地理切分变细， 而不是朝向 / 装修 / 楼层。

方法论收获：一元解释力（η²）不能用来判断「一个字段有没有用」。 一个字段的 η² 接近 0，只说明它单独没用，不说明它在组合里没用。 本项目差点因为这张图把第二版判成失败 —— 是模型分数把它救了回来。

07

调参买不到分数：瓶颈在特征

两版各调了一遍 —— 两版都证明了同一件事

第一版用网格搜索（05_tune.py），第二版用随机搜索 （13_tune_v2.py，在 GroupKFold 上搜、也在 GroupKFold 上报）。 两版的答案是一样的：调参有没有用，完全看调的是哪个模型。

第一版：网格搜索（results/tuning_results.csv）

口径为 5 折 CV R²。Ridge 的 alpha 在 0.001~1000 之间对数等分取了 25 组候选。

第二版：随机搜索（results/tuning_results_v2.csv）

口径为 GroupKFold R²。每个模型 24 组随机候选，两组超参同时汇报。

第一版：Ridge.alpha 从 0.001 搜到 1000，净提升 — —— 调了等于没调。 不是交叉验证调参没意义，而是这份数据的瓶颈不在超参数上。

但同样是调参，KNN 的 k 网格有效（—）、 多项式次数也有效（—）。 结论：交叉验证调参救不了一个本来就不合适的模型，只能让合适的模型更好一点。

一条推翻了教科书的实测结果。教材讲「alpha 小 → 过拟合，大 → 欠拟合」， 但在这份数据上只有右半边成立：alpha 从 — 到约 —， 训练得分和验证得分整条几乎重合、最大训练-验证缝隙只有 — （— 行喂 11 个数值特征， 模型复杂度远小于样本量能支撑的规模）—— 而且这道最大的缝出现在最右端， 不在左边。要到 alpha ≈ — 才跌破峰值 2 个百分点，到 1000 时验证得分掉到 —，那才是欠拟合 —— 惩罚大到把真实信号也压掉了。

作为对照，右侧 KNN 那条才是教科书式的过拟合：k=1 时训练得分 —（满分，每个点最近的邻居就是它自己）、 验证得分只有 —， 缝隙 —； k 增大后两条线靠拢，在 k=— 处验证得分最高。

图上的子标题是按实测缝隙算出来的，不是写死的 —— 照抄教科书会让图在骗人： 读者会去找那道「缝」，而图上根本没有。过拟合不是线性模型的固有病， 是「模型复杂度 ÷ 样本量」不够小时的病。

08

局限与未覆盖的部分

把「已知局限」变成「已知数字」，比假装没有更有价值

  1. 交叉验证有乐观偏差，第二版已量化。同一小区可能有多套房，普通 KFold 会把它们分到训练集和验证集两侧。第二版有了小区标识列，把这一条从「已知局限」 升级成「已知数字」：落差中位数 — —— 第一版报告的 — 若按「预测一个没见过的小区」来评估， 要打掉约 —。
    两个设计要点：① 两套 CV 都必须先打乱行序 —— GroupKFold 本身不打乱，而原始 CSV 按板块 / 环线排序， 打乱只改变「哪些小区进哪一折」、不破坏小区完整性； ② 这条修得不彻底 —— 按小区分组只挡住「同小区泄露」， 没有挡住「相邻小区的泄露」，空间自相关依然存在于组与组之间。 严格该按地理区块分折，但第二版数据源不含经纬度列，做不了。
    一个排除性验证（results/unseen_plate.csv）： 逐折统计「训练集没见过的板块」有多少样本 —— 两套 CV 共 — 折， 合计 — 行 （最大占比 —%）， 等于没有，所以落差只能来自「同小区 / 邻近小区的 房子被切到两边」—— 排除掉一个替代解释，比多测一个数字更有意义。
  2. 没有独立测试集做最终验证。留出集同时承担了「调参后验一次」的角色， 严格来说它已经被看过了。本项目没有第二个留出集可用。
  3. 部署的模型和报告的指标不是同一个对象。06_export.py 里的模型 是在全部 — 行上重新拟合的， 而报告里的 — / — 描述的是泛化能力； 页头显示的 RMSE 来自留出集。三者服务不同目的，不能互相替代。
  4. 部署的不是分数最高的那个模型。第一版 CV 最高的是 — （—），比部署的 Ridge 高 —；但第九节的输入框是开放域， 二次多项式在训练区间之外会掉头向下（「关注人数填 500」能算出负单价）。 这一分精度不值得换外推风险，所以部署 Ridge、并给每个输入框卡了取值范围。
  5. 第二版是挂牌价不是成交价，其所有数字描述的是「预测卖方要价」； 整张对比表的排名都受「统一超参」这个前提约束，CatBoost 的名次 只在这套超参下成立（它没有调过参，也不假装调过）。 两份数据采集时间距今已有若干年、与当前市场无关；原始数据仓库标注 仅供学习使用，本项目仅用于课程练习，不作商业用途。

刻意没做的部分：聚类（KMeans、模糊 C 均值）、PCA 降维、分类算法 （KNN 分类、决策树、朴素贝叶斯、SVM、神经网络）—— 与本题（预测连续价格）无关。

明确不做的工程决定：① 不上测试框架 / lint —— 唯一的自动化校验是导出网页时的 三道检查（模板里的数字路径与元素引用是否都存在、页面脚本能否通过语法检查、 以及 JS 与 Python 逐行比对 — 行预测值）， 它们覆盖的正是真会出错的地方； ② 估价器只用第一版的线性模型 —— 第二版的结果以图表形式汇报（第四~七节）， 但不能接进估价器：Ridge 只有 39 个系数、可以逐行搬进 JS 并与 Python 对到 —， 而 GBDT 集成要在 JS 里重实现三个库的分裂逻辑，那样「页面显示的数」和 「Python 算的数」就只能各写一份、慢慢漂移；③ 不给 CatBoost 调参 （单次拟合 20 秒上下，24 组候选 × 5 折要几十分钟，宁可不调、并写明「没调过」， 也不假装调过）。

想继续改进，按性价比排序：① 补数据 —— 学区、楼层、朝向、房本年限 （已做大部分，收益 —）； ② 用 GroupKFold(groups=小区) 得到无偏估计 （已做，偏差 —）； ③ 年份窗口再收窄到季度级别，或用时间序列交叉验证，让评估更贴近「预测未来」。
