# 北京二手房单价预测
《Python机器学习教程》第 7 章「综合练习」的完整实现：用真实链家二手房数据预测北京二手房**单价（元/㎡）**。第一版只用教程讲过的算法（§一~§八），第二版换用字段更全的挂牌数据、按文献调研引入梯度提升树与堆叠集成（§九），两版并存、收益分开量化。
**三个数带走**：第一版 5 模型 R² **+0.696**；第二版 9 模型 GroupKFold 最高 **+0.8135**；「换数据 +0.0917」与「换模型 +0.0840」收益相当，两件事都要做。
## 一、题目与做法
`4-Python机器学习教程.pdf` 第 50 页第 7 章「综合练习」全文只有一句：「应用上述算法思想对股票、房价（新房、二手房）进行预测，或者根据一些个人信息对要购买的物品进行推荐。」
**没给数据、没指定算法、没给评分标准**，所以选题、取数、建模、交付全部自定：自找可下载可复现的真实数据（链家北京二手房成交 **318,851 条**）；第一版只挑教程讲过的回归算法（§6.1）与交叉验证调参（§2.6.5）；把「采集 → 清洗 → 探索 → 建模 → 调参 → 交付」拆成 6 个可独立运行、全部幂等的脚本。§九起**有意打破「只用教程里的模型」这条自我约束**，依据见 `MODEL_SELECTION.md`。

## 三、为什么目标是「单价」而不是「总价」
目标是「每平米的价格」，**面积在定义上就被除掉了**：`corr(面积, 单价) = -0.219`，而 `corr(面积, 总价) = +0.688`（`fig02`）—— 这是「预测单价」这个目标选择的全部代价。单价六成以上的波动由「在哪个区」决定（区县 η² = **0.627**，`fig03`）。
还有一个**辛普森悖论**（`fig06`）：全市合并看 `corr(房龄, 单价) = +0.328`（房子越老越贵？），按区县分别看 13 条相关系数**符号是混的**（-0.39 ~ +0.33），扣掉区县均值后整体只剩 **+0.064** —— 真相是老房子集中在核心城区（海淀 +0.33）、新房集中在近郊远郊（石景山 -0.39）。R² 停在 0.70 是因为数据没采集学区 / 朝向 / 楼层，**缺的是数据不是算法**（§九验证并修正了这个结论）。
## 四、数据
**第一版**：GitHub `sni13/HousingPrice_Beijing`，第三方从**链家网北京二手房**公开页面采集，**318,851 条 × 26 字段**，成交时间跨 2002–2018 年。只取 **2017 年**（`common.py` 的 `WINDOW_YEARS`）：全量单价**年度**中位数从 15,380（2010）涨到 62,331（2017）元/㎡，**跨 4.05 倍**（`results/price_span.csv`），混在一起建模学到的大半是「**这套房是哪年卖的**」而不是「这套房值多少」；单一年份因此**不需要把「成交年月」放进特征**，价格纯由房屋属性解释。清洗后 **43,213 行 × 17 列**（11 数值 + 5 类别特征），阈值定得很宽（单价 5,000~200,000 元/㎡、面积 10~1,000 ㎡），只剔 4 行录入错误。
**第二版**：Kaggle 二手房挂牌数据集，清洗后 **73,625 行**（1.7 倍），多出朝向 / 板块 / 环线 / 带看量等字段，并**有了小区标识**（6,833 个小区）。⚠️ 第二版是**挂牌价**（卖方要价），第一版是**成交价**，绝对价格不可比，但 R² 这类相对指标可比 —— 跨版本对比一律用 R²。
**两条不可违反的约定**：① **缺失值一律保留 NaN**，交给 Pipeline 里的 `SimpleImputer` —— 先手工填成中位数会让「填补」这一步躲开交叉验证，等于训练时偷看验证集的中位数；② **异常值不删**，IQR 之外的点是核心城区与远郊的真实价差，按 IQR 硬删会切掉最贵的核心区样本，等于把最有效的预测依据删了。另：原始编码是 **GB18030 不是 UTF-8**；`district` 等字段是**没有码表的数字代码**，现有中文映射从数据**实证**得出（按代码分组算平均经纬度 + 10 个公开地标反查，60/60 命中），网上流传的「1=板楼、4=平房」**与数据矛盾，是错的**。
## 五、防数据泄露（本项目最要紧的正确性问题）
`common.py` 的 `guard_no_leakage()` 用**三道关**：① 列名黑名单 `LEAK_NAME_PATTERN`（匹配 `价格|总价|单价|首付|万元|_万$|price`）；② 显式排除列表 `DROP_ALWAYS`（`单价`(目标) / `totalPrice` / `communityAverage` / 经纬度 / `DOM` / 标识符）；③ **单特征交叉验证筛查**，每个特征单独预测目标、CV R² 超过 **0.35** 判泄露。下面两列是特意留在特征集里跑一遍筛查、让结果落进 `results/leak_screen.csv` 的，它们是「为什么不能只看相关系数」的证据：
**`小区均价` —— 数值判据抓得住，名字拦不住。** 列名里没有「价格」二字，黑名单拦不住；+0.932 的相关系数用常见的 0.95 阈值也拦不住；但它单独预测一次目标 R² 就是 **+0.868**，一测就露馅（同小区均价是用**包括这一套在内**的房源算出来的）—— 只有第三关拦得住。
**`总价_万` —— 两道数值判据都抓不住，只有语义判断抓得住。** 它与目标的相关只有 **+0.473**、单特征 R² 只有 **+0.223**，**两道数值判据都会放它过去**；但 `总价_万 × 10000 ÷ 面积` 与单价的相关是 **0.9999999998** —— 总价和面积一起递进去，等于把目标原样递了进去，真把它放进特征再跑一遍 Ridge：CV R² 从 **+0.678 虚高到 +0.868**（`results/leak_demo.csv`，由 `04_regression.py` 落盘）。数值判据看不见它，是因为**线性模型自己造不出「比值」这个非线性组合** —— 判据的有效性依赖于测试它用的模型类别。
**不要为了「特征更多」把价格派生量、按区县 / 小区分组的均价加回来**（target encoding 泄露）。`02_clean.py` 有断言：建模表里不允许出现 `DROP_ALWAYS` 的任何一列。
## 六、稀有类别：一个真实踩到的建模缺陷
one-hot + 线性模型给每个类别一个**自由系数**，而系数是拿该类别的样本估出来的：`建筑类型 = 平房` **只有 1 行** → 系数 **+11,363 元/㎡**；`建筑结构` 的 30 / 13 / 37 行取值同样是数万元/㎡量级。一行样本估出来的系数不是知识，是噪声 —— 而**这个模型有一个网页界面**，谁勾了「平房」，这 +11,363 元/㎡ 就凭空冒出来，看起来和别的数字一样可信。
**修的过程里踩的第二个坑**：最初的修法是「把稀有取值并成『其他』」，**没修好** —— 平房并成「其他」之后**这个桶本身还是 1 行**，照样拿到 +10,460 元/㎡ 的系数。最终方案是**两步走**（`MIN_CATEGORY_COUNT = 200`）：① 稀有取值并成「其他」；② 并完桶还不够 200 行就设为 NaN，交给 `SimpleImputer(most_frequent)` 归进最常见那一档。**200 的依据**：单价标准差约 24,000，n=200 时均值标准误 ≈ `std/√n` ≈ 1,700 元/㎡，已和要估的效应同量级。这个阈值刚好并掉平房(1) / 结构1(30) / 结构3(13) / 结构5(37)，而 **13 个区县里最少的门头沟有 267 行、全部保留**（区县是页面上必须能选的维度）。修完后最大的系数是 `区县 = 西城 +44,366 元/㎡`，估它的样本有 3,844 行。
## 七、第一版实测（`04_regression.py` / `05_tune.py`）
`train_test_split(test_size=0.2, random_state=42)` → 34,570 训练 / 8,643 留出；交叉验证用 `KFold(n_splits=5, shuffle=True, random_state=42)`。RMSE 单位元/㎡。

| 模型 | 5折 CV R² | CV 标准差 | 留出集 R² | 留出集 RMSE |
|---|---|---|---|---|
| 均值基线 `DummyRegressor(strategy='mean')` | -0.000 | 0.000 | -0.000 | 24,468 |
| 线性回归 `LinearRegression` | +0.678 | 0.006 | +0.688 | 13,669 |
| 岭回归 `Ridge(alpha=1)` | +0.678 | 0.006 | +0.688 | 13,669 |
| **岭回归+多项式 `Ridge+Poly2`** | **+0.696** | 0.005 | **+0.704** | **13,306** |
| K近邻回归 `KNN(k=5)` | +0.604 | 0.013 | +0.608 | 15,323 |

**均值基线 R² ≈ 0**，RMSE 24,468 差不多就是单价标准差 24,324 —— 印证了「什么都没学到」，这个数就是及格线。**冠军 `Ridge+Poly2` 只比不带多项式的 Ridge 高 1.8 个百分点**，而 CV 标准差是 0.005 —— 赢得真实，但赢得很小。**KNN 差 9 个百分点**，根因是**维度灾难**：43,213 个样本摊在几十维的 0/1 空间里，「邻居」这个概念的区分度就下降了，把 k 从 1 调到 60 也治不好 —— 它不是参数问题，是特征表示问题。线性回归和 `Ridge(alpha=1)` **完全同分**（11 个数值特征都标准化过、one-hot 列都是 0/1，本就没什么共线性可罚）。
**调参**：`Ridge.alpha` 从 0.001 搜到 1000（25 组对数等分）净提升 **+0.000**；KNN 的 k 网格 **+0.005**；多项式的次数与 alpha 一起搜 **+0.024**（网格自己选了 **degree=3**，CV R² 到 **+0.702**）。**调参有没有用完全看调的是哪个模型 —— 交叉验证调参救不了一个本来就不合适的模型，只能让合适的模型更好一点。** `fig09` 左图还**推翻了教科书的默认图景**：教程 §2.4 讲「alpha 小 → 过拟合，大 → 欠拟合」，但这份数据上**只有右半边成立** —— alpha 从 0.001 到约 0.178，训练得分和验证得分整条几乎重合、**最大缝隙只有 0.0008**，而且这道最大的缝出现在**最右端**（欠拟合那一头）、不在左边（43,213 行喂 11 个数值特征，模型复杂度远小于样本量能支撑的规模）；要到 alpha ≈ **562** 才跌破峰值 2 个百分点、到 1000 时验证得分掉到 **0.621**，那才是欠拟合；右图 KNN 则是**教科书式的过拟合**（k=1 时训练得分 **1.000**、验证只有 **0.422**，缝隙 0.578）。子图副标题**按实测缝隙算出来，不是写死的**。
**一个由样本量决定的结论翻转**：同一段代码、同一份数据源，`Ridge+Poly2` 在 306 行时 CV R² 是 **+0.008**（多项式彻底失败），在 43,213 行时是 **+0.696**（5 个固定模型里排第一）—— 多项式把维度撑得很开（现在这份数据的 11 个数值特征经平方和两两乘积是 77 维；当年那 306 行只有 8 个数值特征、展开后 44 维，仍是样本量的 7 倍），多出来的维度**要靠样本量喂饱**。所以「多项式会不会炸」**不是算法的固有属性，而是「模型复杂度 ÷ 样本量」的函数**。
## 八、汇报网页与图表（`06_export.py` → `web/index.html`）
**单个 HTML 文件，双击就开，离线可用，不依赖任何后端，一份文件兼两个用途：课堂汇报的主体，和可现场操作的估价器。** 汇报部分是**九节**（题目与做法 / 防泄露 / 第一版 5 模型 / 第二版 9 模型 × 2 套 CV / 换数据 vs 换模型 / η² / 调参 / 局限 / 现场演示），开头四张结论卡片给出全部 headline 数字，正文的图分两种：**10 张随浏览器主题换色的内联 SVG**（由注入的 JSON 现画，用于模型对比这类需要跟着页面配色走的图），加上 **13 张实测分析图**（`figures/fig01~fig13`，按 `data:` URI 内嵌，浅底白卡片呈现）—— 后者是文件体积的大头，所以整个 HTML 是 **4.1 MB**：**双击即开、断网也能开，拷到任何机器上都是完整的一份**。估价器部分是左边填 **16 项**房源条件（区县、面积、房间数、楼层位置、装修、电梯/满五/近地铁开关等），右边立刻出预测单价，并告诉这个价钱在 43,213 条成交记录里处于什么位置（全市中位数与该区县中位数对照，各带涨跌百分比）；**误差如实标注**（RMSE 13,669 元/㎡ 写在页头）；另有三张随输入实时重画、随区县下拉框换线的图；相同几条规矩见下 —— **所有指标读数都从产出物注入**： 全文 **179 处**数字写成 `<span data-n="report.xxx:格式">`（这个数会随模板增删而变，`06_export.py` 每次导出都重新数一遍并写进页脚，页面上那个才是最新值），由 `06_export.py` 从 `results/*.csv` 读出来注入，`fillNumbers()` 在初始化时解析 —— **取不到值就抛错**，不静默留个破折号。少数**历史读数**（306 行那份数据上的多项式对照）与**结构性常量**（搜索组数、比对容差）确实在正文里直接写明出处，不走注入 —— 它们是「当时测到的」而非「这次跑出来的」，混进注入反而会随重跑而说谎。为这条规矩，`02_clean.py` / `03_eda.py` / `05_tune.py` / `11_prepare_v2.py` / `12_model_compare.py` / `14_eda_v2.py` 都把本来只打印到控制台的中间量（泄露筛查的相关系数、辛普森的组内 r、验证曲线的 10 个读数、排除性验证、η²）**落盘成 CSV**：要引用就得先写下来，写下来就不会和页面上说的对不上。这条规矩**已经抓出过真错误**：第七节引用的三个验证曲线读数（最大缝隙、开始塌的 alpha、alpha=1000 处的验证得分）原先是从控制台抄进文档的，落盘后重跑发现文档里那份是**更早一次实验的遗留值**，而且它自己前后就对不上（「最大缝隙 0.0004」旁边写着「训练 0.679 vs 验证 0.678」——那是 0.001）。
浏览器里没有 scikit-learn，之所以能做到**精确**而不是近似，是因为最终模型是**线性**的：把管线每一步的参数原样搬到 JS（`SimpleImputer(median)` → `StandardScaler` → `SimpleImputer(most_frequent)` → `OneHotEncoder(handle_unknown="ignore")` → `Ridge` 线性组合）。`web/predict.js` 是这套重放逻辑，**网页和 node 校验脚本共用同一份实现** —— 不会各写一份然后慢慢漂移。三个关键取舍：
- **部署的是 `Ridge(alpha=0.178)`，不是 CV 更高的 `Ridge+Poly2`**：差距 1.8 个百分点，但二次函数在训练区间之外会**掉头向下**（「关注人数填 500」能算出负单价），而网页输入域是开放的 —— 这一分精度不值得拿外推风险去换；同理每个输入框都用 `FORM_RANGES` 卡了范围。
- **导出参数一律按 `float64` 原样写，不做任何四舍五入**：曾经为了「让 JSON 好看」留 6 位小数，一万多的 one-hot 系数乘上去误差到 `1e-2` 量级，被 node 校验抓出来。
- **三道校验缺一不可，失败即 `assert` 拒绝发布**：① 模板里的 179 处数字路径与 36 处 `$("id")` 元素引用是否真的存在（`verify_template_refs`）；② 用 node 的 `vm.Script` 编译页面内联脚本（只查语法）；③ 用 `predict.js` 把 **43,213 行整表跑一遍**与 Python 逐行比对，实测最大差值 **5.821e-11 元/㎡**。三者分别堵三个洞，都是**踩坑之后补上的**：模板里多写一个 `}` 时页面打开是空表而 ③ 仍打印 ✓（它验的是 `predict.js` 里的预测函数，与页面脚本是两份代码）→ 补了 ②；改模板时删掉了一个 `<span>` 指向的元素、`fillNumbers` 抛 TypeError 整页数字全不填，而 ②③ 都只验预测逻辑 → 补了 ①。比较用的期望值**不能取整**，否则光期望值自己带的 `5e-7` 误差就会淹没真差异；没装 node 时 ②③ 打印 `[跳过]` 并提示「网页逻辑未经验证」，页脚也如实写这句（**这条路径靠模拟 node 缺失跑过一遍**，因为本机永远有 node）。

## 九、第二版：换数据 + 换模型（`10`~`15`）
第一版 R² 停在 0.696，§三的结论是「缺的是数据不是算法」。这一节把那个结论**验证一遍、也修正它**：先换数据，再按文献换模型。**不采用「文献说 X 好就用 X」**——那是把别人数据集上的结论硬套过来；做法是**四个 GBDT 全放进去，用自己这份数据实测**（选型依据见 `MODEL_SELECTION.md`）。两组交叉验证**并排跑**，超参数在对比阶段**一律相同**（`n_estimators=400, learning_rate=0.06`），否则「哪个模型好」和「谁调得更狠」会混在一起。RMSE 单位元/㎡。

### XGBoost 与 CatBoost：两个「垫底」的不同成因
**XGBoost 是四个 GBDT 里最弱的一个，它的形状是「一直持平、忽然掉一折」，而不是「处处都差」**（`results/model_folds_v2.csv`）：逐折 0.7965 / 0.7864 / **0.7151** / 0.8002 / 0.7949，与另外三个 GBDT 的同折均值相比，**落后超过 0.001 的有 3 折（折 2 / 折 3 / 折 5），其中折 3 一折就占全部落后量的 67.7%**（折 1 与折 4 和同折均值持平，折 4 甚至高 0.0003 —— 所以「每一折都低」这个说法是错的）。折间极差 **0.0851，是另外三个 GBDT 的 1.9~3.1 倍**。*一个我自己做了但没做成的验证，如实记下*：本想用三个随机种子（42 / 7 / 2024）看坏折是不是偶然，结果三次逐折分数**一模一样** —— 因为 XGBoost 默认 `subsample=1`、`colsample_bytree=1`，**根本没有随机性可换**；所以这个实验**证明不了「偶然 vs 结构性」**，它的实际信息是该配置下 XGBoost 是**确定性**的、坏折是数据划分的固有性质。**⚠️ CatBoost 的 GroupKFold 排倒数第二（主口径上垫底的是 XGBoost，两者只差 0.0003、实质并列；CatBoost 真正垫底的是普通 KFold 与留出集），比 HistGBR 低 3.4 个点，但它只是「没训够」**：乐观落差 0.0247（**在四个 GBDT 里最小**；全场排第 4，两个线性模型比它更小）+ 普通 KFold 下的折间标准差 0.0019（**全场最低，均值基线除外**）是**欠拟合**的特征 —— 对照 XGBoost，分数一样低但 GroupKFold 折间标准差 0.0321，抖得多，那是另一回事；单独扫迭代数（其余超参不动；`results/cat_iter_scan.csv`，`src/15_cat_iter_scan.py` 产出，协议与主表同源），400 → 800 → 1600 轮是 +0.7790 → +0.7895 → **+0.7954**，**单调上升、到 1600 轮还没收敛**。所以「CatBoost 比另外三个差 5 个点」这个读法**没有依据**，差距里很大一块是**同一套超参对不同库的适配度**；**但别把话说满** —— 到 1600 轮它仍低 1.8 个点，本次实验**只证明了「排名会随迭代数移动」**。
### 再调超参买不到分数：瓶颈在特征
**再调超参还有空间吗？没有**（`13_tune_v2.py`，**在 GroupKFold 上搜、也在 GroupKFold 上报**）：24 组随机候选，LightGBM +0.8112 → +0.8120（**+0.0008**）、HistGBR +0.8135 → +0.8130（**−0.0004**），**都远小于折间标准差 0.0105 —— 调参在这份数据上买不到分数**，默认超参已贴着上限。这不是失败，而是一条结论：**瓶颈在特征，不在超参**。**顺带一个方法论观察**：调参让 **KFold** 分数涨了约 +0.006，却让 **GroupKFold** 纹丝不动 —— 按 KFold 选超参会选到一组「更会利用同小区泄露」的参数，分数看着涨了、真实泛化能力没动；**这就是「搜索口径必须等于汇报口径」的实证理由**。
### 把「已知局限」变成「已知数字」：乐观偏差 0.0402
**把「已知局限」变成「已知数字」**：第一版承认了「KFold 有乐观偏差」但修不了（没有小区标识列），第二版有了 `community`，于是**量化**出来 —— 普通 KFold 比 GroupKFold 高 **0.0402（中位数）**，第一版报告的 0.696 若按「预测一个没见过的小区」来评估，**大约要打 4 个百分点的折扣**。两个设计要点：① **两套 CV 都必须先打乱行序** —— `GroupKFold` 本身不打乱，而原始 CSV 按板块 / 环线排序，打乱只改变「哪些小区进哪一折」、**不破坏小区完整性**（`common_v2.shuffle_once()`）；② **这条修得不彻底** —— 按小区分组只挡住「同小区泄露」，**没有**挡住「相邻小区的泄露」，空间自相关依然存在于组与组之间，严格该按**地理区块**分折，但第二版数据源不含经纬度列。**一个排除性验证**（`results/unseen_plate.csv`，由 `12_model_compare.py` 的 `unseen_plate()` 产生）：逐折统计「训练集没见过的板块」有多少样本 —— 两套 CV 共 10 折，**合计 0 行**（每一折的占比都是 0.0000%），等于没有，所以落差**只能**来自「同小区 / 邻近小区的房子被切到两边」—— **排除掉一个替代解释，比多测一个数字更有意义**。
### 换数据 vs 换模型：+0.0917 与 +0.0840
**「换数据」和「换模型」各值多少**：关键是**同一个 Ridge 跑在两份数据上**，把「数据」这一项单独隔离出来（`fig11`）：第一版 Ridge（成交价 4.3 万行）KFold R² **+0.6780** → 换数据 **+0.7697**（**+0.0917**）→ 换模型（Ridge → HistGBR）**+0.8537**（**+0.0840**），合计 +0.1757。**结论：两件事都要做** —— 第一版说「缺的是数据不是算法」方向是对的（换数据确实涨 9 个点），但**模型侧的余量同样可观**，这一点第一版没看到，因为它只试了教程里那四个模型，而它们全是线性 / 距离类、**吃不下特征之间的交互**。⚠️ **口径说明**：上面两段的**数值**只能在**普通 KFold** 下比（第一版没有小区列，GroupKFold 算不出来）；但「换模型」这一步**选谁当冠军是按主口径 GroupKFold 定的**（HistGBR）—— 普通 KFold 的最大值其实属于**堆叠**（+0.8553），可它只在 KFold 上赢，拿它算收益等于用一把偏乐观的尺子去量收益。
### 反直觉：新字段的一元解释力很低
**一个反直觉的发现：新字段的一元解释力很低**（`14_eda_v2.py`，η² = 组间方差 / 总方差）：**板块**（129 个取值）**0.6415**、**环线**（6 个取值）0.5068、**朝向**（11 个取值）0.0368、**装修** 0.0097、**楼层位置** **0.0016（小到可以忽略）**。关键要**分成两栏看，而不是按大小排**：**地理维度看着强，但它不新** —— 第一版的「区县」13 个取值就有 0.627，板块只是把同一件事切得更细（129 个取值），一元解释力只从 0.627 挪到 0.642，**地理信息在第一版就已经吃满了**；**非地理维度（朝向 / 装修 / 楼层位置）才是真正新开的信息轴，而它低一个数量级** —— 说「一个数量级」还说轻了：最强的非地理字段（朝向 0.0368）对上最强的地理字段（板块 0.6415）是 **17.4 倍**（三者全部低于 0.05）。只从这张表看应该得出「换数据几乎白换」，可实测模型分数明明涨了 —— **两个数字对不上，对不上的部分只能来自特征之间的交互**（「同一个板块里朝向好的更贵」「同一个小区里楼层不同价不同」，这类信息在**任何一个单变量的统计量里都看不见**）。**这里有一个第一版没料到的结果**：换数据之后连**线性模型都涨了 +0.0917**，原以为「Ridge 造不出交互项、所以吃不下新字段」，实测它吃得下不少 —— 多出来的解释力来自**地理切分变细**（13 个区县 → 129 个板块 + 6 个环线），而不是来自朝向 / 装修 / 楼层，后者只有树模型按分裂逐层组合才能利用。
### 换数据踩到的三个坑（都不报错或报错指不到根因）
**换数据踩到的三个坑，三个都不报错或报错指不到根因**（细节在 `CLAUDE.md` §五）：① **`ColumnTransformer` 把数值列变成 object** —— 它把各列 hstack 成一个数组，float64 与 object 混在一起会被统一提升成 object，改用 `GbdtFrame` 逐列构造 DataFrame；② **`X.iloc[:, i] = ....astype("category")` 是无效赋值** —— iloc 就地写入已有的 object 块，pandas 会把 Categorical 还原成原值、dtype 一点没变，**不报任何错**，必须用标签赋值 `X[c] = ...`；③ **XGBoost 按类别「下标」读数据** —— 训练折和验证折各推一套类别表、顺序未必相同，下标一错位整列含义就变了，**表现是 GroupKFold 的 R² 掉成 -0.1461（负数！）而 KFold 一切正常**，修法是类别表在 `fit` 时**定死**。另外两条更简单的：CatBoost 的 `get_params()` 返回 `cat_features` 的**副本**，撞上 `sklearn.clone`「构造器必须原样保存参数」的硬断言，做交叉验证一定崩；自定义估计器的继承顺序必须是 `(RegressorMixin, BaseEstimator)`，反了的话 `estimator_type` 是 `None`，堆叠集成会拒绝它。
## 十、局限与未覆盖的部分

1. **交叉验证有乐观偏差**：同一小区可能有多套房，普通 `KFold` 会把它们分到训练集和验证集两侧。严格的画法是 `GroupKFold(groups=小区)`，但第一版数据里没有小区标识列。**→ 第二版已量化：偏差中位数 0.0402，第一版所有数字大约要打 4 个百分点的折扣（§九）；而 GroupKFold 本身仍偏乐观**，因为它挡不住相邻小区的空间自相关。
2. **没有独立测试集做最终验证**：留出集同时承担了「调参后验一次」的角色，严格来说它已经被看过了。
3. **部署的模型和报告的指标不是同一个对象**：`06_export.py` 里的模型是在**全部 43,213 行**上重新拟合的，而报告里的 0.678 / 0.696 描述的是泛化能力；页头显示的 RMSE 来自留出集。
4. **第二版是挂牌价不是成交价**，其所有数字描述的是「预测卖方要价」；整张对比表的排名都受「统一超参」这个前提约束，CatBoost 的名次**只在这套超参下成立**（它**没有调过参**，也不假装调过）。另外，两份数据都是成交价 / 挂牌价，采集时间距今已有若干年、与当前市场无关；原始数据仓库标注**仅供学习使用**，本项目仅用于课程练习，不作商业用途。

**刻意没做的部分**：聚类（KMeans、模糊 C 均值）、PCA 降维、分类算法（KNN 分类、决策树、朴素贝叶斯、SVM、神经网络）—— 与本题（预测连续价格）无关。**明确不做的工程决定**：不上测试框架 / lint（导出网页时的**三道**校验已覆盖真正会出错的地方）；**估价器只用第一版的线性模型** —— 第二版的结果以图表形式汇报（第四~七节），但不接进估价器：Ridge 只有 39 个系数、可以逐行搬进 JS 并与 Python 对到 5.821e-11 元/㎡，而 GBDT 集成要在 JS 里重实现三个库的分裂逻辑，那样「页面显示的数」和「Python 算的数」就只能各写一份、慢慢漂移；不给 CatBoost 调参（单次拟合 20 秒上下，24 组候选 × 5 折要几十分钟，**宁可不调、并写明「没调过」，也不假装调过**）。**想继续改进，按性价比排序**：① 补数据 —— 学区、楼层、朝向、房本年限（**已做大部分，收益 +0.0917**）；② 用 `GroupKFold(groups=小区)` 得到无偏估计（**已做，偏差 0.0402**）；③ 年份窗口再收窄到季度级别，或用时间序列交叉验证，让评估更贴近「预测未来」。
