# 北京二手房单价预测

《Python机器学习教程》第 7 章「综合练习」的完整实现 —— **用真实链家二手房数据预测北京二手房单价（元/㎡）**，算法取自教程：线性回归、岭回归、多项式回归、K 近邻回归 + 交叉验证调参。

**§十三是独立的第二版**：换用字段更全的挂牌数据，并按文献调研引入教程之外的梯度提升树与堆叠集成（`MODEL_SELECTION.md`）；第一版（§一~§十二）仍完整可用，两版并存，收益在 §13.5 分开量化。

## 一、练习出处

`4-Python机器学习教程.pdf` 第 50 页，第 7 章「综合练习」全文只有一句：「应用上述算法思想对股票、房价（新房、二手房）进行预测，或者根据一些个人信息对要购买的物品进行推荐。」

题目**没给数据、没指定算法、没给评分标准**。做法：自己找一份可下载、可复现的真实数据（链家北京二手房成交记录 **318,851 条**）；只挑教程讲过的回归算法（§6.1）与交叉验证调参（§2.6.5）；把「采集 → 清洗 → 探索 → 建模 → 调参 → 交付」拆成 6 个可独立运行的脚本。**第十三节有意打破「只用教程里的模型」这条自我约束**（第一版只到 R² ≈ 0.70），依据见 `MODEL_SELECTION.md`。**预测目标限定为「单价（元/㎡）」而非总价** —— 这个选择本身就是本练习最有价值的部分，见 §四。

## 三、数据

**来源**：GitHub `sni13/HousingPrice_Beijing`，第三方从**链家网北京二手房**公开页面采集，**318,851 条** × 26 字段，成交时间跨 **2002–2018 年**；仓库标注**仅供学习使用**，本项目仅用于课程练习，不作商业用途。

### 3.1 为什么只取 2017 年

全量跨 2002–2018，其间北京单价中位数从 **3.8 万**涨到 **6.6 万**；全量混在一起建模，模型学到的大半会是「**这套房是哪年卖的**」而不是「这套房值多少」—— 那不是估价模型。`common.py` 的 `WINDOW_YEARS` 默认 `(2017, 2017)` → **43,217** 行（年内单价中位数波动 1.17 倍）；`(2016, 2017)` → 134,046 行；`None` → 全量 318,851 行（跨越 1.75 倍价格水位）。既然是单一年份，就**不需要把「成交年月」放进特征**，价格纯由房屋属性解释。

`02_clean.py` 清洗后 **43,213** 行（剔 4 行）：单价须在 5,000~200,000 元/㎡（剔 3 行）、面积须在 10~1,000 ㎡（剔 1 行）、总价不得缺失或非正（剔 0 行）—— 阈值定得很宽，只剔录入错误（原始数据最小单价 **136 元/㎡**）。两个坑在 `01_download.py` 里都处理了：**编码是 GB18030 不是 UTF-8**（`.decode('gb18030')` 再存 UTF-8，让编码问题只在 01 里出现一次）；**GitHub 个人仓库链接会失效**（`SOURCES` 放主/备地址，逐个重试并退避）。

### 3.2 清洗后的建模表

`data/lianjia_bj_clean.csv`，**43,213 行 × 17 列**。目标 `单价`（元/㎡）；**11 个数值特征** `面积` `室` `厅` `卫` `总层数` `房龄` `梯户比` `关注人数` `电梯` `满五` `近地铁`；**5 个类别特征** `区县`(13 个取值) `楼层位置`(5) `装修`(4) `建筑类型`(3) `建筑结构`(3)。

单价 最小/中位数/均值/最大 = 5,008 / **62,332** / 67,119 / 150,000 元/㎡（标准差 24,324）；分位数 1%/25%/75%/99% = 27,758 / 48,997 / 80,788 / 139,013；面积 最小/中位数/最大 = 15.0 / 72.6 / 906.0 ㎡。剩余缺失：房龄 793、建筑类型 478、建筑结构 80、楼层位置 4、梯户比 1。

**缺失值一律保留 NaN**，交给 Pipeline 里的 `SimpleImputer` —— 先手工填成中位数会让「填补」这一步躲开交叉验证，等于训练时偷看验证集的中位数。**异常值也没有删**：IQR 之外的 `单价` 是核心城区与远郊的真实价差（区县对单价的 η² = **0.627**），硬删等于把最有效的预测依据删了。

### 3.3 编码字段是怎么变成中文的

`district`、`renovationCondition`、`buildingType`、`buildingStructure` 在原始数据里都是**数字代码且没有码表**，本项目从数据实证：

- **`district`（区县）**：按代码分组算平均经纬度，再用地标反查（金融街/国贸/中关村/天通苑/果园/亦庄/古城/良乡/顺义/门头沟），每个地标 2km 内最近的 60 套房源 —— **60/60 全部落在预期编码上**。
- **`buildingType`（建筑类型）**：code 1 总层数中位 21 层、98.0% 有电梯；code 4 中位 6 层、26.6%；code 3 中位 17 层、94.6% —— 层数与电梯率两个独立证据互相印证 → 塔楼 / 多层板楼 / 板塔结合。**网上流传的「1=板楼、4=平房」与数据矛盾，是错的。**
- **`renovationCondition`（装修）**：证据弱些，按原样保留 —— code 4 房龄最轻（13 年）、电梯率最高（65.3%）；code 2 单价最低。装修对单价影响本身很小（四档中位数 57,824~63,326，约 9%）。

## 四、先说结论：为什么「单价」比「总价」难得多

本节数字全部来自 `03_eda.py` 的实际输出。

### 4.1 单价几乎由区县决定，而面积几乎不含信息

**区县对单价的 η² = 0.627** —— 单价六成以上的波动由「在哪个区」解释。相关系数：房龄 **+0.328**、近地铁 **+0.325**、面积 **-0.219**、梯户比 -0.131、室/厅/卫 -0.115/-0.097/-0.094、关注人数 -0.066、总层数 -0.005。

**面积为什么关系这么弱？** 因为目标是「每平米的价格」，面积在定义上就被除掉了。总价 = 单价 × 面积，所以面积对**总价**当然有效（`fig02` 右图 r = **+0.688**），对单价却很弱（左图 r = -0.219）—— 这就是「预测单价」这个目标选择的全部代价。

### 4.2 一个辛普森悖论

`fig06`：**全部房源合并看**，`corr(房龄, 单价) = +0.328`，房子越老越贵？**按区县分别看**，13 条相关系数**符号是混的**（**-0.39 到 +0.33**），扣掉区县均值后整体只剩 **+0.064**。真相是老房子集中在核心城区（海淀 `+0.33`、西城 `+0.13`、东城 `+0.04`），新房集中在近郊远郊（石景山 `-0.39`、门头沟 `-0.36`、大兴 `-0.32`、房山 `-0.27`、昌平 `-0.14`、通州 `-0.13`）—— 「区县」这个混杂变量把真实关系整个盖住了。网页上的房龄图会随区县下拉框实时换线：全市虚线向上（+0.328），换到朝阳线基本就平了（+0.046）。

### 4.3 一个由样本量决定的结论翻转

同一段代码、同一份数据源：`Ridge+Poly2` 的 CV R² 在 306 行时是 **+0.005**（多项式彻底失败，等于没学到东西），在 43,213 行时是 **+0.696**（多项式**赢了**，5 个固定模型里排第一）。数值列只有 11 个，平方和两两乘积把数值那一支从 11 维撑到 77 维，多出来的维度**要靠样本量喂饱** —— 306 行时这 77 维是纯噪声，43,213 行时才变成真实信号。`05_tune.py` 让网格把次数和 alpha 一起搜，它选了 **degree=3**，CV R² 进一步到 **+0.702**；306 行时它选的是 degree=1，主动放弃了多项式。所以「多项式会不会炸」**不是算法的固有属性，而是「模型复杂度 ÷ 样本量」的函数** —— 正是教程 §2.4 讲的过拟合。

## 五、防数据泄露（本项目最要紧的正确性问题）

### 5.1 两种泄露，两道判据各抓一个

原始数据里有这么两列，`02_clean.py` 特意把它们**留在特征集里跑一遍筛查**，好让结果落进 `results/leak_screen.csv` —— 这是「为什么不能只看相关系数」的证据：`小区均价` 与单价相关系数 **+0.932**、单特征 CV R² **+0.868**；`总价_万` 相关系数 **+0.473**、单特征 R² **+0.223**。

**`小区均价` —— 数值判据抓得住，名字拦不住。** 列名里没有「价格」二字，黑名单拦不住；+0.932 用常见的 0.95 阈值也拦不住；但它单独预测一次目标 R² 就是 +0.868，一测就露馅 —— 同小区均价是用**包括这一套在内**的房源算出来的。

**`总价_万` —— 两道数值判据都抓不住，只有语义判断抓得住。** 它与目标的相关只有 +0.473、单特征 R² 只有 +0.223，**两道数值判据都会放它过去**。可它是实打实的泄露：`总价_万 × 10000 ÷ 面积` 与单价的相关 = **0.9999999998**（最大差 27.5 元/㎡，是 CSV 里总价只存到整万元造成的舍入）。**总价和面积两列一起递进去，等于把目标原样递了进去** —— 加进特征后 Ridge 的 CV R² 从 **+0.678 跳到 +0.868**。数值判据看不见它，是因为**线性模型自己造不出「比值」这个非线性组合** —— 判据的有效性依赖于测试它用的模型类别。完整对照见 `figures/fig05_leak_screen.png`。

### 5.2 本项目实际用的判据

`common.py` 的 `guard_no_leakage()` 用**三道关**：① **列名黑名单** `LEAK_NAME_PATTERN`（匹配 `价格|总价|单价|首付|万元|_万$|price`，抓 `总价_万`）；② **显式排除列表 `DROP_ALWAYS`**（`单价`(目标) / `totalPrice` / `communityAverage` / `url` / `id` / `Cid` / `tradeTime` / `DOM` / `Lng` / `Lat` / `kitchen`）；③ **单特征交叉验证筛查**（抓 `小区均价`）：每个特征**单独**预测目标，CV R² 超过 **0.35** 判泄露。

阈值 0.35 的依据：`小区均价` 是 **0.868**，必须拦；合法特征里最强的 `近地铁` 只有 **0.106**、`房龄` 0.105，必须留。其余被排除的列：`Lng`/`Lat`（「区县」的更细粒度版本，放进线性模型会得到一张光滑的价格平面，区县系数变得不可读）、`DOM`（挂牌天数，成交后才知道，且「卖得慢」本身可能是价格太高的结果）、`kitchen`（42,829/43,217 都是 1，零方差）、`tradeTime`（只用来切窗口）、`url`/`id`/`Cid`（标识符）。本项目**没有**引入任何按区县/小区分组的均价类特征 —— 那属于 target encoding 泄露。`02_clean.py` 落了一条断言：建模表里不允许出现 `DROP_ALWAYS` 中的任何一列。

## 六、稀有类别：一个真实踩到的建模缺陷

这是本项目**唯一一个不是「算法选错」而是「数据表示有错」的问题**。one-hot + 线性模型给每个类别一个**自由系数**，而系数是拿该类别的样本估出来的：`建筑类型 = 平房` **1 行** → 系数 **+11,363 元/㎡**；`建筑结构 = 结构1` 30 行、`结构3` 13 行、`结构5` 37 行 → 数万元/㎡量级。一行样本估出来的系数不是知识，是噪声 —— 而**这个模型有一个网页界面**，谁勾了「平房」，这 +11,363 元/㎡ 就凭空冒出来，看起来和别的数字一样可信。

**修的过程里踩的第二个坑**：第一版修法是「把稀有取值并成『其他』」，**没修好** —— `建筑类型` 只有 `平房` 一个稀有取值，并成「其他」之后**这个桶本身还是 1 行**，照样拿到 +10,460 元/㎡ 的系数。

最终方案是**两步走**（`MIN_CATEGORY_COUNT = 200`）：① 稀有取值并成「其他」；② 并完之后**桶还不够 200 行**，就把这些行设为 NaN，交给 `SimpleImputer(strategy="most_frequent")` 归进最常见的那一档。**200 怎么定的**：均值标准误约 `std/√n`，单价标准差约 24,000，n=200 时标准误 ≈ 1,700 元/㎡，已和要估的效应同量级。这个阈值刚好并掉 `平房`(1)、`结构1`(30)、`结构3`(13)、`结构5`(37)，而 **13 个区县里最少的门头沟有 267 行，全部保留** —— 区县是用户必须能选的维度。修完后最大的系数是 `区县 = 西城 +44,366 元/㎡`，估它的样本有 3,844 行。

## 七、实测结果

### 7.1 五个模型同台（`04_regression.py`）

`train_test_split(test_size=0.2, random_state=42)` → 34,570 训练 / 8,643 留出；交叉验证用 `KFold(n_splits=5, shuffle=True, random_state=42)`。

| 模型 | 5折 CV R² | CV 标准差 | 留出集 R² | 留出集 RMSE |
|---|---|---|---|---|
| 均值基线 `DummyRegressor(strategy='mean')` | -0.000 | 0.000 | -0.000 | 24,468 |
| 线性回归 `LinearRegression` | +0.678 | 0.006 | +0.688 | 13,669 |
| 岭回归 `Ridge(alpha=1)` | +0.678 | 0.006 | +0.688 | 13,669 |
| **岭回归+多项式 `Ridge+Poly2`** | **+0.696** | 0.005 | **+0.704** | **13,306** |
| K近邻回归 `KNN(k=5)` | +0.604 | 0.013 | +0.608 | 15,323 |

**均值基线 R² ≈ 0**，RMSE 24,468 差不多就是单价标准差 24,324 —— 印证了「什么都没学到」，这个数就是及格线。**冠军是 `Ridge+Poly2`（+0.696）**，但只比不带多项式的 Ridge 高 **1.8 个百分点**，而 CV 标准差是 0.005 —— 赢得真实，但赢得很小（与样本量强相关，见 4.3）。**KNN 差 9 个百分点**，原因见 7.3。线性回归和 Ridge(alpha=1) **完全同分** —— 11 个数值特征都标准化过、几十个 one-hot 列都是 0/1，本就没什么共线性可罚。（上表 RMSE 单位元/㎡）

### 7.2 调参（`05_tune.py`）

| 搜索对象 | 搜索范围 | 最优参数 | 调参前 CV R² | 调参后 CV R² | 净提升 |
|---|---|---|---|---|---|
| `Ridge.alpha` | 0.001 ~ 1000，25 组对数等分 | **alpha = 0.178** | +0.678 | +0.678 | **+0.000** |
| `Ridge` 多项式次数 + alpha | degree ∈ {1,2,3} × alpha 9 组 | **degree = 3, alpha = 3.162** | +0.678 | **+0.702** | **+0.024** |
| `KNN.n_neighbors` | {1,2,3,5,8,12,16,20,25,30,40,60} | **k = 8** | +0.604 | +0.609 | **+0.005** |

调参后的留出集表现：`Ridge(alpha=0.178)` → R² = +0.688、RMSE 13,669 元/㎡；`KNN(k=8)` → +0.611、15,262 元/㎡。**调参有没有用，完全看调的是哪个模型**：Ridge 的 alpha 从 0.001 搜到 1000、25 组候选走完，最高分和最低分**几乎没有区别**（+0.000）—— 瓶颈不在超参数上；同一套代码放在 KNN 上却是 +0.005 的真实提升。交叉验证调参**救不了一个本来就不合适的模型，只能让合适的模型更好一点**。多项式那一栏网格自己选了 degree=3（306 行时它选 degree=1），CV R² 达 +0.702，比 `04` 里固定 `alpha=1` 的 `Ridge+Poly2`（+0.696）还高，因为次数和 alpha 是一起搜的。

**`fig09` 左图推翻了教科书的默认图景。** 教程 §2.4 讲「alpha 小 → 过拟合，大 → 欠拟合」，但这份数据上**只有右半边成立**：alpha 从 0.001 到约 0.178，训练得分和验证得分**整条几乎重合**，最大缝隙只有 **0.0004**（训练 0.679 vs 验证 0.678）—— 惩罚几乎为零时**也不见过拟合**，43,213 行喂 11 个数值特征，模型复杂度远小于样本量能支撑的规模。唯一的边界在右边：alpha 超过约 **31.6** 才开始塌，到 1000 时验证得分掉到 **0.629**，那才是欠拟合。右图 KNN 则是**教科书式的过拟合**：k=1 时训练得分 **1.000**（每个点最近的邻居就是它自己，纯背答案）、验证得分只有 **0.422**，缝隙 0.578；k 增大后两条线靠拢，在 k=8 处验证最高 0.609。所以「过拟合」不是线性模型的固有病，而是**「模型复杂度 ÷ 样本量」不够小时的病**。那张子图的副标题是**按实测缝隙算出来的，不是写死的**。

### 7.3 为什么 KNN 差这么多

KNN 靠「距离」找邻居，而 one-hot 之后特征空间维度不低：43,213 个样本摊在几十维的 0/1 空间里，**「邻居」这个概念的区分度就下降了** —— **维度灾难**，把 k 从 1 调到 60 也治不好。它不是参数问题，是特征表示问题。

### 7.4 为什么 R² 停在 0.70

区县解释了单价的 62.7%，模型做到 0.696。剩下的 30% 来自**数据集根本没采集的信息**：学区、楼层高低与朝向、小区品质、楼栋在小区内的位置、临街与否、装修实际品质……这些在真实二手房价里每一项都能差出 10%~30%。**模型已经把数据里有的信息基本榨干了，缺的是数据，不是算法**（这个结论在 §13.5 被验证，也被修正）。

## 九、预测界面（`src/06_export.py` → `web/index.html`）

左边填房源条件，右边立刻出预测单价，并告诉这个价钱在 43,213 条成交记录里处于什么位置。**单个 HTML 文件，双击就开，离线可用，不依赖任何后端。**

### 9.1 怎么让网页算出和 Python 一模一样的数

浏览器里没有 scikit-learn。之所以能做到**精确**而不是近似，是因为最终模型是**线性**的：`Ridge` 的预测就是 `截距 + Σ 系数 × 特征`。于是把管线每一步的参数原样搬到 JS：`SimpleImputer(median)` → `impute_median`；`StandardScaler` → `scaler_mean`/`scaler_scale`，算 `(v-mean)/scale`；`SimpleImputer(most_frequent)` → `cat_fill`；`OneHotEncoder(handle_unknown="ignore")` → `categories`，命中第 i 个类别则第 i 位为 1，否则全 0；`Ridge` → `coef`/`intercept`，线性组合。`web/predict.js` 就是这套重放逻辑，**网页和校验脚本共用同一份实现** —— 不会各写一份然后慢慢漂移。

### 9.2 部署的是 Ridge，不是冠军 Poly2

`Ridge` CV R² +0.678 / 留出集 RMSE 13,669 元/㎡，`Ridge+Poly2` +0.696 / 13,306 元/㎡，差距约 **0.6%**。但代价是把平方项交给用户随便填的数：二次函数在训练区间之外会**掉头向下**，「关注人数填 500」能算出负单价，而网页的输入域是开放的 —— 这一分精度不值得拿外推风险去换。同理，每个数值输入框都用 `FORM_RANGES` 卡了范围（面积 10–400 ㎡、房龄 0–70 年、总层数 1–50、梯户比 0–2、关注人数 0–500）。

### 9.3 怎么确认两边算的是同一件事

导出的参数**不做任何四舍五入**。这点踩过坑：最初为了「让 JSON 好看点」把 `scaler` 留 6 位小数、系数留 10 位有效数字，结果 one-hot 的系数动辄上万，这点截断误差乘上去能到 `1e-2` 元/㎡ 量级 —— 被 node 校验第一轮抓出来。现在一律按 `float64` 原样导出，校验分两道，都会 `assert`，失败就拒绝发布：**第一道**用 node 的 `vm.Script` 把 `index.html` 里的内联脚本编译一遍（只查语法）；**第二道**用 `predict.js` 把 **43,213 行数据整表跑一遍**，与 Python 逐行比对，差值超过 `1e-6` 元/㎡ 就报错 —— 实测最大差值 **5.821e-11 元/㎡**（相对 `5.8e-16`，约 2 个 ULP），而网页把价格显示到整数位，这点差别连显示的最后一位都影响不到。

两道缺一不可，第一道是**踩坑之后补上的**：模板里曾经多写了一个 `}`，页面打开是一张空表，而第二道校验打印的却是 ✓，因为第二道验的是 `predict.js` 里的**预测函数**，它和页面脚本是两份代码。比较用的期望值也**不能取整** —— 若写 `round(..., 6)`，光期望值自己就带了 `5e-7` 的误差，会把真正的差异淹没。没装 node 时两道都打印 `[跳过]` 并继续，但会明确提示「网页逻辑未经验证」。

### 9.4 页面上有什么

**16 个输入项**（区县、面积、房间数、厅数、卫生间数、楼栋总层数、梯户比、挂牌关注人数、楼层位置、装修、建筑类型、建筑结构，外加电梯/满五/近地铁三个开关；房间数/厅数/卫生间数是**下拉框**，取值从数据里读出来）；**预测结果**（大字单价值 + 房源摘要）+ **两个对照**（全市中位数与该区县中位数，各带涨跌百分比）；**误差如实标注**（RMSE 13,669 元/㎡ 写在页头）；**三张随输入实时重画的图** —— 单价分布（全市 43,213 套与该区县房源各按自己的总量折算成百分比后并排，橙色竖线是预测）、面积 vs 单价（抽样 1,476 个点，蓝线是**全部 43,213 套**按面积十分位的中位数）、房龄 vs 单价（全市虚线 `r = +0.328` 与该区县实线，§4.2 的直观版）。

**数据量：能精确的都在 Python 侧算准，只有散点才抽样。** 直方图、分箱中位数线、拟合线 / r 值 / 区县中位数全部用**全部 43,213 行**，只有散点抽样 1,476 行并标明「抽样」。43,213 行不可能整表塞进网页，但直方图、分位数这些统计量本身很小 —— 33 个箱 × 14 条 = 462 个整数，携带的信息量和整表一样。几个刻意的取舍：**直方图两条分布各自折算成百分比**（否则全市四万多条对区县几百条，两个量级画在同一计数轴上，区县那条直接看不见）；**趋势线在 Python 侧算好再导出**（网页上的 `r` 值必然与 `fig02`/`fig06` 一致）；**横轴截至 99% 分位**（面积最大 906 ㎡，按最大值铺满会把 99% 的房源压成左边一条竖线）；**分箱线横坐标用箱内中位面积**而非箱边界中点（最右一箱 `(114, 906]` 的中点 510 落在几乎没有房源的地方，该箱实际中位面积只有约 170）；**`|r| < 0.05` 时不写方向**（朝阳房龄 `r = +0.046` 写成「越老越贵」是过度解读 —— 0.046 解释的方差是 0.2%）。

## 十、教程 API → 现代 scikit-learn 对应表

教程写作时间较早，不少 API 已被移除或改名，本项目统一用现代 API。**已移除、需改模块路径的六个**：`grid_search.GridSearchCV`、`cross_validation.train_test_split`、`cross_validation.cross_val_score`、`cross_validation.KFold` → `model_selection.*`；`datasets.samples_generator.make_blobs` → `datasets.make_blobs`；`preprocessing.Imputer` → `impute.SimpleImputer`。**改名 / 改行为的四个**：`LinearRegression(normalize=True)` 参数已删除 → 标准化交给 Pipeline 里的 `StandardScaler`；`OneHotEncoder(sparse=False)` → `sparse_output=False`；`KFold(n_splits=5)`（不打乱）仍可用但不推荐 → `shuffle=True, random_state=42`；`make_pipeline(('name', est), ...)` **1.9 起不再接受 `(名字, 估计器)` 元组** → `Pipeline([('name', est), ...])`。最后一条是本项目实际踩到的坑，其余几条（含 pandas 3 的两个静默坑）连同复现方式都记在 `CLAUDE.md` §五。

## 十一、局限与未覆盖的部分

1. **交叉验证有乐观偏差**：同一小区可能有多套房，普通 `KFold` 会把它们分到训练集和验证集两侧。严格的画法是 `GroupKFold(groups=小区)`，但第一版数据里没有小区标识列。**→ 第二版已量化：偏差中位数 0.0402，第一版所有数字大约要打 4 个百分点的折扣（§13.4）。**
2. **没有独立测试集做最终验证**：留出集同时承担了「调参后验一次」的角色，严格来说它已经被看过了。
3. **部署的模型和报告的指标不是同一个对象**：`06_export.py` 里的模型是在**全部 43,213 行**上重新拟合的，而 README 里的 0.678 / 0.696 描述的是泛化能力；页头显示的 RMSE 来自留出集。
4. **数据是成交价**，采集时间距今已有若干年，与当前市场无关。

**刻意没做的部分**：聚类（KMeans、模糊 C 均值）、PCA 降维、分类算法（KNN 分类、决策树、朴素贝叶斯、SVM、神经网络）—— 与本题（预测连续价格）无关。**明确不做的工程决定**：不上测试框架 / lint（唯一的自动化校验 node 双校验已覆盖真正会出错的地方，上 pytest 是形式主义）；不把第二版结果接进 `web/index.html`（网页是第一版的交付物，第二版没有配套导出脚本，两版并存、各自自洽比强行合并一个半成品好）；不给 CatBoost 调参（单次拟合 20 秒上下，24 组候选 × 5 折要几十分钟，**宁可不调、并写明「没调过」，也不假装调过**，§13.3 / §13.8）。**想继续改进，按性价比排序**：① 补数据 —— 学区、楼层、朝向、房本年限（**→ 第二版已补大部分，收益 +0.0917，§13.5**）；② 用 `GroupKFold(groups=小区)` 得到无偏估计（**→ 已做，偏差 0.0402，§13.4**）；③ 年份窗口再收窄到季度级别，或用时间序列交叉验证，让评估更贴近「预测未来」。

## 十三、第二版：换数据 + 换模型（`10`~`14`）

第一版的 R² 停在 **0.696**，§7.4 的结论是「**缺的是数据不是算法**」。这一节把那个结论**验证一遍** —— 先换数据，再按文献换模型。

### 13.1 为什么换数据，换的是什么

§7.4 点名缺失的是学区、朝向、楼层、小区品质。换用的 Kaggle 二手房挂牌数据集正好补上其中大部分：样本量 43,213 → **73,625 行**（1.7 倍）；特征 11 数值 + 4 类别 → 11 数值 + 5 类别，**多出**朝向/楼层位置/板块/环线/近公园/带看量/关注人数；**有了小区标识**（6,833 个小区，平均 10.8 套，第一版没有）；失去经纬度、精确地铁距离、成交日期。

⚠️ **口径差异必须说清楚**：第二版是**挂牌价**（卖方要价），第一版是**成交价**，两者数值不可直接比较（挂牌价普遍高于成交价），但**建模方法论完全一致**，R² 这类相对指标仍然可比 —— 报告中所有跨版本对比都是 R²，不是绝对价格。

### 13.2 换模型：文献依据

完整的调研见 `MODEL_SELECTION.md`：多份独立研究一致报告**梯度提升树稳定优于线性模型**；但「CatBoost / XGBoost / LightGBM 谁第一」**随数据集变**，没有普适冠军（Ames 数据上 XGBoost 第一、CatBoost 紧随；马德里数据上随机森林反而最高）；**堆叠集成（三个 GBDT + Ridge 元学习器）在文献里一致优于任何单一模型**（R² 约 0.933 vs 单模型最好 0.9298）。本项目**不采用**「文献说 X 好就用 X」这种论证 —— 那是把别人数据集上的结论硬套过来；做法是**四个 GBDT 全放进去，用自己这份数据实测**。

### 13.3 实测：9 个模型同台（`12_model_compare.py`）

两组交叉验证**并排跑**，超参数在对比阶段**一律相同**（`n_estimators=400, learning_rate=0.06`）—— 否则「哪个模型好」和「谁调得更狠」会混在一起。

| 模型 | 普通 KFold R² | **GroupKFold R²** | 乐观落差 | 留出集 RMSE | 拟合¹ |
|---|---|---|---|---|---|
| **直方图梯度提升 HistGBR** | +0.8537 | **+0.8135** | 0.0402 | 11,767 | 1.9 s |
| 堆叠 GBDT×4 → Ridge | +0.8553 | +0.8124 | 0.0429 | 11,674 | 68 s |
| LightGBM | +0.8540 | +0.8112 | 0.0428 | 11,812 | 0.9 s |
| CatBoost | +0.8037 | +0.7790 | 0.0247 | 13,571 | 21 s |
| XGBoost | +0.8316 | +0.7786 | 0.0530 | 11,699 | 1.3 s |
| 岭回归 Ridge | +0.7697 | +0.7595 | 0.0102 | 14,775 | 0.2 s |
| 线性回归 | +0.7697 | +0.7595 | 0.0102 | 14,775 | 0.6 s |
| K近邻 KNN(k=5) | +0.6738 | +0.5970 | 0.0768 | 17,615 | 0.2 s |
| 均值基线 DummyRegressor | -0.0001 | -0.0067 | 0.0066 | 30,618 | 0.1 s |

（RMSE 单位元/㎡）¹ **拟合耗时是墙钟时间，不是可复现的测量结果** —— 两次运行可以差 1.5 倍（本表这一列就是从「1.2 / 56 / 0.7 / 14 / 0.9 s」那次运行更新过来的，模型分数一位没变，只有时间变了），**只用来比较同一次运行内谁比谁慢**。其余各列都是确定性的。

- **GBDT 家族整体比线性模型高 5~9 个百分点**（0.811 vs 0.760，GroupKFold 口径），与文献一致。**冠军是 HistGBR（+0.8135）**，但它和堆叠、LightGBM 的差距只有 0.001~0.002 —— **远小于折间标准差 0.0105**，正确的说法是**「前三个打平」**，不是「HistGBR 最好」。
- **⚠️ 堆叠没有赢。** 文献说堆叠必胜，这份数据上它 KFold 第一（+0.8553）、GroupKFold 却掉到第二（+0.8124）。**这是本项目和文献不一致的地方，如实报告。** 可能原因：基模型之间太像（HistGBR 与 LightGBM 分数差 0.0003），元学习器没有互补信息可用，反而多了一层过拟合。
- **KNN 的落差最大（0.0768）**，因为它完全靠「附近样本的均值」预测，对空间结构最敏感（§7.3）。
- **XGBoost 是四个 GBDT 里最弱的一个，且不只是「某一折运气差」**（`results/model_folds_v2.csv`）：GroupKFold 逐折 0.7965 / 0.7864 / **0.7151** / 0.8002 / 0.7949，**每一折都低于三个 GBDT 的同折均值**（0.8052 / 0.8293 / 0.7996 / 0.8202 / 0.8075），去掉最差的第 3 折后均值也只从 0.7786 回到 0.7945，仍低于另外三个的 0.8124；**折间极差 0.0851，是其余四个 GBDT（LightGBM 0.0275、HistGBR 0.0297、堆叠 0.0317、CatBoost 0.0440）的 2~3 倍**，也是它 KFold 标准差 0.0323（别人 0.0019~0.0042）的来源。**一个我自己做了但没做成的验证，如实记下**：本想用三个随机种子（42 / 7 / 2024）看坏折是不是偶然，结果三次逐折分数**一模一样**（0.8521 / 0.8478 / 0.8583 / 0.7698 / 0.8302）—— 因为 XGBoost 默认 `subsample=1`、`colsample_bytree=1`，**根本没有随机性可换**；所以这个实验**证明不了「偶然 vs 结构性」**，它的实际信息是：该配置下 XGBoost 是**确定性**的，坏折是数据划分的固有性质。
- **⚠️ CatBoost 垫底（GroupKFold 比 HistGBR 低 3.5 个点，KFold 低 5.0 个点），但它只是「没训够」—— 已实测确认。** 两条**表内**证据：乐观落差 0.0247（全场最小）、折间标准差 0.0019（全场最低）—— 「落差小 + 方差低」是**欠拟合**的特征（过拟合会掉得更狠，对照 XGBoost 的 0.0530）。本表里**所有模型一律 400 轮**，而 CatBoost 要对 129 个板块取值算有序目标统计量，本来就需要更多轮。单独跑迭代数扫描（其余超参不动）：400 轮 +0.7790（−0.0345）、800 轮 +0.7895（−0.0240）、1600 轮 **+0.7954**（**−0.0181**）—— **单调上升，到 1600 轮还没收敛**。所以「CatBoost 比另外三个差 5 个点」这个读法**没有依据**：差距里有很大一块是**同一套超参对不同库的适配度**。但**别把话说满**：扫描到 1600 轮它仍低 1.8 个点，本次实验**没有**证明它追得上，只证明了「排名会随迭代数移动」。

**那再调超参还有空间吗？没有。**（`13_tune_v2.py`）在 **GroupKFold 上搜、也在 GroupKFold 上报**，24 组随机候选：LightGBM +0.8112 → +0.8120（**+0.0008**，376 s）、HistGBR +0.8135 → +0.8130（**−0.0004**，83 s）。**两个提升都远小于折间标准差 0.0105 —— 调参在这份数据上买不到分数**，默认超参已经贴着上限。这不是失败，而是一条结论：**瓶颈在特征，不在超参**，和 §13.6 对得上 —— 新字段的一元解释力接近 0，价值全在**特征交互**里，而交互是树模型自己分裂出来的。**顺带一个方法论观察**：调参让 **KFold** 分数涨了（0.8540 → 0.8598、0.8537 → 0.8602，各约 +0.006），却让 **GroupKFold** 纹丝不动 —— 按 KFold 选超参会选到一组「更会利用同小区泄露」的参数，分数看着涨了、真实泛化能力没动；这就是「搜索口径必须等于汇报口径」的实证理由。

### 13.4 把「已知局限」变成「已知数字」：乐观偏差

第一版 §十一 #1 承认了「KFold 有乐观偏差」但修不了（没有小区标识列）；第二版有 `community`，所以这条现在**量化**出来了：**普通 KFold 比 GroupKFold 高 0.0402（中位数）** —— 第一版报告的 0.696，如果按「预测一个没见过的小区」来评估，**大约要打 4 个百分点的折扣**。这不是本项目独有的问题，空间自相关领域的文献（`MODEL_SELECTION.md` §四）结论一致：随机划分的 CV 会**系统性高估**，因为它让训练集和验证集里出现空间上紧邻的房子。

**两个实验设计要点：** ① **两套 CV 都必须先打乱行序** —— `GroupKFold` 本身不打乱，而原始 CSV 按板块/环线排序，直接跑会让「没见过的小区」和「没见过的区域」混在一起，落差归因不清；打乱只改变「哪些小区进哪一折」，**不破坏小区完整性**（`common_v2.shuffle_once()`）。② **这条修得不彻底**：按小区分组只挡住「同小区泄露」，**没有**挡住「相邻小区的泄露」—— 空间自相关依然存在于组与组之间，所以 GroupKFold 的结果**仍然偏乐观**；严格的做法是按**地理区块**分折，但第二版数据源本身就不含经纬度列。

**一个排除性验证：落差不是「类别没见全」造成的。** 逐折统计「训练集没见过的板块」占比，**普通 KFold 和 GroupKFold 的每一折都是 0.00%** —— 因为 `merge_rare` 之后 129 个板块每个都至少有 200 行，6,833 个小区分到 5 折，训练集那一侧总能覆盖全部 129 个取值。所以落差**只能**来自「同小区 / 邻近小区的房子被切到了两边」，正是我们声称的机制。**排除掉一个替代解释，比多测一个数字更有意义。**

### 13.5 「换数据」和「换模型」各值多少

关键是**同一个 Ridge 跑在两份数据上**，把「数据」这一项单独隔离出来（`figures/fig11_data_vs_model.png`）：

```
第一版 Ridge（成交价 4.3 万行）      KFold R²  +0.6780
  ＋换数据                            →  +0.7697    收益 +0.0917
  ＋换模型（Ridge → HistGBR）          →  +0.8537    收益 +0.0840
                                      ─────────────────────────
                                          合计 +0.1757
```

**结论：换数据（+0.0917）和换模型（+0.0840）收益相当，两件事都要做。** 第一版 §7.4 说「缺的是数据不是算法」，方向是对的 —— 换数据确实涨了 9 个点；但**模型侧的余量同样可观**，这一点第一版没看到，因为它只试了教程里的四个模型，而它们全都是线性/距离类模型，**吃不下特征之间的交互**（见 13.6）。

⚠️ **口径说明（容易串台，特意写明）**：上面两段的**数值**只能在**普通 KFold** 下比 —— 第一版没有小区列，GroupKFold 算不出来；但「换模型」这一步**选谁当冠军是按主口径 GroupKFold 定的**（HistGBR）。普通 KFold 的最大值其实属于**堆叠**（+0.8553，比 HistGBR 高 0.0017），可它只在 KFold 上赢、GroupKFold 上反而更低（§13.3）—— 拿它算收益，等于用一把偏乐观的尺子去量收益。

### 13.6 一个反直觉的发现：新字段的一元解释力很低

把这些字段单独拿去解释房价（`14_eda_v2.py`，η² = 组间方差/总方差）：**板块**（129 个取值）η² = **0.6415**，比第一版最强的「区县」只高 +0.0145；**环线**（6 个取值）0.5068，单看很强，但它是「板块」的粗粒度版本；**朝向**（11 个取值）0.0368，比第一版的「近地铁」(0.1056) 还低；**装修**（4 个取值）0.0097；**楼层位置**（4 个取值）**0.0016，等于零**（fig13 里柱子高度看不见）。

关键在**分成两栏看，而不是按大小排**：**地理维度（板块 0.642、环线 0.507）看着强，但它不新** —— 第一版的「区县」13 个取值就有 0.627，板块只是把同一件事切得更细（129 个取值），一元解释力只从 0.627 挪到 0.642，**地理信息在第一版就已经吃满了**；**非地理维度（朝向/装修/楼层位置）才是真正新开的信息轴，而它低一个数量级**，三者全部低于 0.05。

所以只从这张表看，应该得出「换数据几乎白换」的结论 —— 可实测模型分数明明涨了。**两个数字对不上**，对不上的部分只能来自**特征之间的交互**：「同一个板块里朝向好的更贵」「同一个小区里楼层不同价不同」，这类信息在**任何一个单变量的统计量里都看不见**，只存在于组合中。**这里有一个第一版没料到的结果**：换数据之后连**线性模型都涨了 +0.0917**（同一 Ridge：0.6780 → 0.7697），原以为「Ridge 造不出交互项，所以吃不下新字段」，实测它吃得下不少 —— 多出来的解释力来自**地理切分变细**（13 个区县 → 129 个板块 + 6 个环线），而不是来自朝向/装修/楼层，后者只有树模型按分裂逐层组合才能利用。

### 13.7 换数据过程中踩到的三个坑

三个都**不报错或报错指不到根因**（细节在 `CLAUDE.md` §五）：

1. **`ColumnTransformer` 把数值列变成 object**：它把各列 hstack 成一个数组，float64 和 object 混在一起会被统一提升成 object。改成逐列构造 DataFrame（`common_v2.GbdtFrame`）。
2. **`.iloc[:, i] = ....astype("category")` 是无效赋值**：iloc 是就地写入已有的 object 块，pandas 会把 Categorical 还原成原值，dtype 一点没变，**不报任何错**。必须用标签赋值 `X[c] = ...`。
3. **XGBoost 按类别「下标」读数据**：训练折和验证折各自现推一套类别表，顺序未必相同，下标一错位整列含义就变了 —— 不报错，只是把「南北」当成「东」。表现是 GroupKFold 的 R² 掉成 **-0.1461**（负数！），而 KFold 一切正常。修法：类别表在 `fit` 时**定死**，验证折里没见过的取值按缺失处理。LightGBM 和 CatBoost 按类别**取值**处理，没这个问题。

另外两个更简单的：CatBoost 的 `get_params()` 返回 `cat_features` 的**副本**，而 `sklearn.clone` 有一条「构造器必须原样保存参数」的硬断言，做交叉验证一定撞上；自定义估计器的继承顺序必须是 `(RegressorMixin, BaseEstimator)`，反了的话 `estimator_type` 是 `None`，堆叠集成会拒绝它。

### 13.8 本节的局限

1. **挂牌价 ≠ 成交价**，本节所有数字描述的是「预测卖方要价」。
2. **GroupKFold 仍偏乐观**（§13.4），只是比 KFold 诚实 —— 按小区分组挡不住「相邻小区」的空间自相关。
3. **CatBoost 的分数不代表它的能力上限**（§13.3）：迭代数扫描已实测确认它只是没训够（400 → 1600 轮，0.7790 单调升到 0.7954，仍未收敛）；**本次实验没有为它调参**，所以它在表里的名次**只在这套超参下成立**。
4. **整张对比表的排名都受「统一超参」这个前提约束**：用同一套超参是为了排除「谁调得更狠」这个混淆项，代价是排名不等于各库的最佳水平。
5. **调参的结论（§13.3）也只在「24 组随机候选」这个预算下成立**：搜索覆盖了 `n_estimators` / `learning_rate` / 叶子数 / `min_child_samples` / `l2`，但没碰 `max_depth`、`subsample`、`colsample` 和类别处理的相关超参。
6. **XGBoost 的坏折没有查出成因**：三个种子给出完全相同的分数，是因为它的默认配置无随机性可换，这个验证**没能回答**「偶然还是结构性」。
7. **没有独立测试集**，留出集在对比和调参中被反复看过（同第一版 §十一 #2）。
